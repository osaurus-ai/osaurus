# Settings Overview

Workflows opens from the second icon in the main window navigation rail. It is no longer a Settings section. Settings search still finds workflow controls and opens that main surface. Chat is the default first destination; Architect authoring belongs to Workflows.

Settings… (⌘,) opens the Management window. Type a name in the sidebar search to jump to a control; when few settings match exactly, close spellings follow, one typo per word ("hotky" finds Global Hotkey). Below the settings, **Your Items** lists your own agents, workflows, downloaded models, MCP servers and providers whose name matches; choosing one opens it. The built-in assistant uses the same catalog via `osaurus_help` `{action: find}` — it will quote a breadcrumb, not invent a path.

Ask the assistant to change declarative settings in chat (`osaurus_config`); each change shows a one-tap approval card first (see the Declarative Configuration topic).

## Tied head codec

Settings → Server → Settings → Decode Performance → **Tied LM Head Codec** controls optional conversion of an unquantized tied embedding in an otherwise quantized model. **Passthrough (model load dtype)** keeps the unconverted head and the loader's effective activation dtype; it does not promise FP16. The 4/6/8-bit choices trade head precision for size while preserving that effective activation dtype. Save Changes applies the choice on the next model load. Cache state is isolated between codecs and loader precision contracts.

## Agent descriptions

Each agent has an optional **Brief description (optional)** field on the agent's page (Settings → Agents → the agent). It is a one-line summary of what the agent does and when to delegate to it, shown beside the agent's name wherever the Orchestrator or an agent picker lists targets. It is never required: agents with a blank description can still be saved, duplicated, and delegated to.

When the description is blank and the agent has a system prompt, Osaurus generates a summary in the background (using the configured core model, or the model already loaded for chat) and shows it as the field's placeholder. Generation never blocks a save and never loads a model on its own; it runs after a chat turn completes or when the Orchestrator builds its delegation roster. Typing your own description overrides the generated one; editing the system prompt regenerates it. Description text is routing metadata and never grants tools or permissions.

## Agent runtimes

An agent runs on Osaurus's own loop by default. To run it on an external harness instead, register the harness under Settings… (⌘,) → **Agent Runtimes** (in the Capabilities group) (**Add Runtime**: protocol, name, executable, arguments, environment), then pick it from the chat's model picker (each runtime is a column next to the model providers; Claude Code lists Sonnet, Opus, Fable, and Haiku) or in Settings → Agents → the agent → Configure → **Runtime** → **Runs on**. Both change the same per-agent setting, so the agent's later chats use it too; picking a model row switches the agent back to Osaurus's own loop. Runtime switches are disabled while a reply is running. Claude Code is registered on first launch; Pi and Pi-based harnesses use the **Pi (RPC)** protocol with `--mode rpc` in their arguments.

- Each chat gets its own long-running harness process, started in the chat's folder (or a private per-chat scratch folder when none is set). Changing the folder restarts the process there after the current reply; Claude Code resumes its conversation, and a Pi runtime resumes when its arguments include `--session-id {chat_id}` (new Pi runtimes start with it).
- The harness brings its own tools (and, for Pi, its own model). In chat the model picker chip shows the runtime's name, plus the Claude model for Claude Code; Osaurus abilities, memory, and the sandbox don't apply to that agent.
- **Test** starts the runtime once (Pi answers `get_state`; Claude Code reports its sign-in). **Sign In** on a Claude Code runtime opens Claude Code's own browser sign-in, with a Terminal fallback.
- For Claude Code agents, **Claude Code Options** (Claude model, Claude effort, Execution mode, Allow file changes, Allow shell commands, Allow Osaurus read tools, Allow Osaurus configuration changes) appear under the agent's Configure tab. Claude effort is passed to Claude Code as `--effort`; Default leaves Claude Code on its own per-model default. The same setting appears as Reasoning Effort in the chat model picker when a Claude Code row is selected, and a change applies from the next message. Claude Code's thinking summaries are turned on, so its reasoning shows in the reasoning panel. File changes are limited to the chat folder; shell commands and Pi tools can't be confined. Allow Osaurus configuration changes is available on the Default agent only.
- The Architect can also run on a harness: pick the runtime's column in the Architect chat's model picker. There it keeps its own instructions and reaches only its workflow tools through the Osaurus server; Claude Code Options and Pi's built-in tools don't apply to it. A proposed save shows the Save card when the reply ends.
- Agents on a harness can't be the target of `spawn_agent`, `/agents/{id}/run`, Computer Use, or AppleScript; those return an error naming the harness instead of running with different settings.
- Harness authors: see `docs/HARNESS_RUNTIMES.md` for the environment variables (`OSAURUS_CHAT_ID`, `OSAURUS_AGENT_ID`, `OSAURUS_AGENT_TOKEN`, …) and what the agent token may call.

## What the assistant can change in chat

- The Orchestrator (itself): display name, model, temperature, max output tokens, persona (system prompt).
- Memory: enabled, budget tokens, retention days.
- Model Defaults: **Core Model** and **Compaction Model** (`model_defaults`). The image, video, speech, privacy detection and AppleScript models stay in Settings.
- Chat: Smooth Streaming, Group Thinking & Tool Activity, Expand Thinking While Streaming, Check Spelling While Typing, Automatically Name Chats, Suggest Follow-Up Questions, Clipboard Monitoring, and Keep Mac Awake While Agents Run (`chat`).
- General: **Global Hotkey**, **Start at Login** and **Show Notifications** (`app`).
- Agents: create/update custom agents, capability toggles, which agent new chats open with (`new_chat_agent`), and which built-in **Apple Apps** a custom agent may use (`capabilities.apple_apps`, e.g. `["calendar", "reminders"]`). The Orchestrator never calls the Apple app tools itself; ask it to "give Planner access to Calendar" or "create a Mail agent" and it patches or provisions the custom agent.
- Tools: global enablement and permission policies.
- Delegation: allowed subagents (custom agents and teammates' shared agents as `Name@Workspace`), per-workspace auto-join, spawn permissions, and the per-subagent limits (tokens, turns, seconds, local/remote parallelism).
- Workflows: list installed workflows, run one with `run_workflow` (only workflows marked **Osaurus can run this for you**), and choose which workflows a custom agent gets as tools (`agents[].workflows`). Installing, setup, secrets, and saved answers stay in Main window → Workflows.
- Agent runtimes: register a harness (`harness_runtimes`) and move an agent onto it (`runtime` and `claude_code` on the agent or `default_agent`). Each needs your approval: the plan flags a new harness command, a changed command line or environment, an agent moving onto a harness, and Claude Code's shell or configuration-change permission.
- Plus everything else the declarative document covers: models, providers, MCP servers, plugins, commands, knowledge collections, channel settings, automations (schedules, folder watches, webhooks, feeds, event streams, failed runs and app events), channel routing (Email included), and web-search providers.

## What lives only in the Settings UI

- Server: port, expose to network, generation defaults, batching/concurrency, prefix/paged-KV/disk cache, **Context Window Cap**, KV retention, memory safety (**Mode**, **Safety Level**, **Keep Model in Memory**, and Advanced Overrides: **Fail Closed When Estimate Is Unknown**, **Custom Physical Memory Fraction**, **Allocator Cache Cap (MB)**, **Max Concurrent Sequences**), model exposure. (Port and exposure changes restart the server; cache topology changes unload loaded models; disk-size changes update resident quotas.)
- Server → Settings → Authentication → **Require Access Key for Local Admin Routes** (off by default): callers on this Mac must send an access key to `/sessions`, `/agents`, `/conversations/*`, `/mcp/*`, `/admin/config/*` and `/admin/import/*`, and browser pages are refused on those routes unless their origin is listed by name in **Allowed Origins (CORS)** under Server → Settings → Connection (`*` does not count). Siri and Shortcuts keep working. Takes effect on the next request; no restart. Access keys themselves are created in Server → Overview. An Osaurus bundle can set this, and add to Allowed Origins, during `osaurus import`.
- Orchestrator: Settings → Orchestrator (under Agents) holds **Identity** (**Name** and **Avatar**: upload your own image or pick a dino), **Instructions** (**System Prompt**), Model & Generation (with the **Model Readiness** row), **Working Folder**, Subagents (one row, **Allowed Subagents and Limits**, which opens Agents → Delegation), and the **Delegations** list (Sent / Received), then **Danger Zone** → **Restore Defaults** for the identity settings. The working folder and the Delegations list are UI-only; the rest is also declarative (`default_agent`).
- Delegation: Settings → Agents → Delegation (under **Working Together** on the Agents page) holds Subagents (**Allowed subagents**, **Create starter agents**, **Add all agents** — shown only while the list is empty but agents exist, **Permission**, **Permission for shared (workspace) agents**, **Limits**, **Advanced**) and Local Models & Memory (**Swap Local Models for Subagents**, **Check Memory Before Delegating**). Allowed subagents is the Orchestrator's list; custom agents set their own on their Subagents tab. Local Models & Memory is shared by every agent. The model override and RAM-safety helpers are UI-only; the rest is also declarative (`delegation`).
- Projects: Settings → Context → **Projects** is the only place projects are created, edited and deleted (`osaurus_config` cannot change them). **New Project** asks for a **Name** and **Default Agent**. A project's page has **General** (**Name**, **Default Agent**), **Instructions** (added after the agent's own System Prompt in every chat in the project), **Knowledge** (collections granted to every chat in the project, on top of the agent's own; **New Collection** opens Knowledge and grants the new collection to the project), **Working Folder** (new chats in the project open in it, in place of the agent's own Working Folder; a folder picked in the chat still wins), **Shared Memory** → **Open in Memory** (Memory → Agents & Projects), and **Danger Zone** → **Delete Project** (chats are kept and leave the project; its shared memory is cleared). Each existing project appears in the chat sidebar as its own collapsible group below Agents, listing its chats: the group's **+** starts a chat with the Default Agent (or the window's agent when none is set), and its gear opens the project here. Chats join or leave a project through **Move to Project** in a chat's ⋯ menu.
- Architect: Settings → Architect (under Agents) customizes the built-in workflow designer. **Identity** has **Name** and **Avatar** (upload your own image or pick a dino). **Instructions** has **Extra Instructions**, which are added to the Architect's built-in instructions and cannot replace them. **Model** has **Architect Model**. **Permissions** sets whether the Architect asks first, runs without asking, or never runs a tool: **Edit the Draft** (`workflow_draft`) and **Run Test Workflows** (`workflow_test`) both run without asking by default. Saving a draft as a real workflow always asks you. These live in `~/.osaurus/config/architect.json` and are UI-only. **Danger Zone** → **Restore Defaults** resets the name, avatar, and instructions.
- Configurator: Settings → Configurator (under Agents) customizes the built-in helper that answers questions about Osaurus and makes settings changes when you ask in chat. It works behind your chats and is never in the agent picker. **Identity** shows its **Name**, which is fixed. **Instructions** has **Extra Instructions**, added to its built-in instructions. **Model & Generation** has **Configurator Model** (unset uses the Orchestrator's model) and **Temperature** (off uses the model's own default). Every change it makes still shows an approval card first. These live in `~/.osaurus/config/configurator.json` and are also declarative (`configurator`). **Configuration History** lists every recorded version of your setup (agents, models, tools, automations and the other declarative settings), newest first, with when it changed, who changed it (the Configurator, **Changed in Settings**, a template install, a file import, your iPhone, or the command line) and which parts. Select one version to see what it changed, or two to compare them; each row's ⋯ menu has **Name…** (named versions are always kept; otherwise the newest 200 are), **Export…** (the version as a `.yaml` file) and **Revert to This Version…**, which shows the same approval card as a chat change. Server runtime settings, keys and tokens, appearance, voice and working folders are not versioned. **Danger Zone** → **Restore Defaults** clears the instructions, model, and temperature.
- Chat (Settings → Chat): a **Commands** row at the top, then **Transcript** (Smooth Streaming, Group Thinking & Tool Activity, Expand Thinking While Streaming), **Composer** (Check Spelling While Typing, Collapse Long Pastes, ⌘+N Starts a New Chat in the Current Window), **Behavior** (Automatically Name Chats, Suggest Follow-Up Questions, Clipboard Monitoring, and, while the Onboarding agent is on, **Show Discovery Cards** — one card under the greeting of a new chat, at most one new card a day, and the Set Up Osaurus link; **Skip setup** beside that link turns it off too — and **Set Up Osaurus**, which opens a chat listing what is left to set up), **Models** (**Core Model** and **Compaction Model**, both links to Models → Model Defaults), and an **Advanced** disclosure with Top P Override, Max Tool Attempts (The Architect always gets at least 80 per message; a higher value applies to it too) and a **Context Window Cap** link to Server → Cache, where the context window is set. The switches are also declarative (`chat`); ⌘+N, Collapse Long Pastes, Show Discovery Cards, Top P and Max Tool Attempts are not.
- Agents → the custom agent → Sandbox → Execution → **Code Can Use Osaurus** (off by default): lets commands and plugins in that agent's sandbox run model completions (`osaurus-host inference chat`), start agent tasks (`osaurus-host agent dispatch`), and register plugins (`osaurus-host plugin create`) through Osaurus. When it is off those calls are refused (registering through the agent's own plugin tool still works and asks you first); a plugin's own `permissions.inference` does not turn them on. A task started this way runs unattended: tools that would ask you first are refused.
- Workspaces → *workspace* → Shared Agents → **Require Approval for Teammate Tool Calls** (per agent hosted on this Mac; declarative `agents[].shared_tool_approval`): a teammate's call to a tool that needs approval waits for you instead of failing. See the Workspaces topic.
- Workspaces → *workspace* → Shared Agents → **Decline Unanswered Requests After** (below the switch above, available once it is on; declarative `agents[].shared_tool_approval.timeout_seconds`): how long that call waits before it is declined, 5 minutes to 24 hours (10 minutes by default).
- Workspaces → *workspace* → **Workflows**: the workflows and agent templates members shared with the workspace (Share → **Who can see it** → **Workspace**), each with **Install** or **Update**; the copy runs on your Mac. The author, owners, and admins have **Remove from workspace**. **Open in Workflows** shows the same list in Main window → Workflows → **Workspaces**. UI-only. See the Workspaces topic.
- A workflow's setup → **Agents** (when it has agent steps): **Choose…** an agent for each step, and **Allow Without Asking**, saved on that workflow only, so its scheduled and automation runs don't stop at an agent step (Agents → Delegation → **Permission** is unchanged, and its Deny still applies). See the Workflows topic.
- General → **Notifications**: **Show Notifications**, then one row per kind of "needs you" moment — **Approvals**, **Questions from Agents**, **Inbound Messages**, **Shared Agent Conversations**, **Agent Notifications** — each with a menu that checks where it reaches you: **In the app**, **Desktop**, **iPhone** (the button reads the choice, such as *In the app, iPhone*, or *Off*; **iPhone** reaches the Osaurus iPhone app through Sync once you add it under Sharing → Devices). **Push (coming soon)** is listed but not available yet. **In the app** can't be picked while **Show Notifications** is off. Desktop notifications for approvals offer **Allow** / **Deny** (and **Allow for This Conversation** for a teammate's request); questions and messages offer **Reply**. **Desktop Notifications Only in the Background** (on by default) keeps desktop notifications quiet while you're using the app. UI-only. Every answered or expired item is recorded in Insights → **Interactions**.
- General: **Appearance** (Appearance, Text Size), **Startup** (Global Hotkey, Start at Login, Hide Dock Icon), **Power** (Keep Mac Awake While Agents Run), **Updates** (Beta Updates), **Notifications**, **Legal**, and **Danger Zone** with **Factory Reset…** at the very bottom. General is about the app: the models folder and models already on this Mac are Local Models → **Sources**, and encryption, backup and file history are Privacy & Security → **Data & Storage**. Global Hotkey, Start at Login and Show Notifications are also declarative (`app`), and Keep Mac Awake is declarative under `chat`.
- Models → **Model Defaults**: every "which model is used for X" choice on one page. **Text** (**Core Model** for background jobs such as titles, memory distillation and transcript cleanup; **Compaction Model** — unset = the chat's current model summarizes; compaction runs automatically near the context limit and on demand from the **Compact conversation** button in the chat's context budget popover or the `/compact` command; when set, this model summarizes every chat regardless of the chat's own model; summary requests use Thinking Off only when the model supports it, without changing chat or saved agent defaults, and incomplete or non-shrinking summaries are never applied), **Images & Video** (**Image Generation Model**, **Edit Model**, **Text-to-Video Model**, **Image-to-Video Model**, **Image Model Load Policy**), **Speech** (**Speech-to-Text Model**), **Privacy Detection** (**Detection Model**), and **AppleScript** (**AppleScript Model**, **AppleScript Model Residency**), then **Downloads & Updates** (**Automatically Check Model Updates** and **Open Local Models**). Agents can override these per agent. Core Model and Compaction Model are also declarative (`model_defaults`).
- Models → **Local Models**: one page for every on-device model, switched with **Model kind**: **Language**, **Image**, **Speech**, **Privacy Detection** and **AppleScript**. Each kind is one table (**Fits This Mac**, memory, size, released, status) with **All** / **On This Mac** / **Available**, search and sortable columns; clicking a row opens its details on the right. **Sources** in its header opens **Model Sources**: **Models Folder** (where Osaurus downloads and stores its own models) and **Use Models Already on This Mac** (the Hugging Face cache or a model folder, LM Studio, and **Rescan**; files are used in place, never copied).
- Voice: **Voice Input in Chat** on the page itself, then **Setup** (microphone, speech model, detection sensitivity), **Transcription** (system-wide dictation hotkey, stop behavior, cleanup), **Text to Speech** (voice, preview; engine under Advanced) and **Wake Word**. **Speech Models** opens Local Models → Speech; the default speech model is in Model Defaults.
- Appearance (General → **Appearance**): **Appearance** is **System**, **Light** or **Dark** for every window (System follows macOS); the same choice is in the menu bar under View → Appearance. **Text Size** scales text everywhere (70% to 160%, default 100%) and is the same value View → Zoom In / Zoom Out / Actual Size change. Custom themes were removed: there is no theme gallery, editor, import or per-agent theme any more, and a custom theme that was active becomes Light or Dark to match it. UI-only.
- Computer & Browser Use: Computer Use setup and its on/off switch, then **Autonomy** (presets, per-app rules, allowlist, cloud vision), **Screen Context**, **AppleScript** (Automation permission and how generated scripts are gated), **Browser Use** (sessions) and **AppleScript Models** (opens Local Models → AppleScript).
- Sandbox (Developer Tools → Sandbox): most people never need this page; on Macs that run the sandbox VM, its runtime downloads quietly in the background after onboarding (the VM does not start), and the sandbox starts from that download the first time an agent runs a command, with chat showing **Preparing sandbox** in that turn. Each agent runs in its own Linux container and user and sees only its own home and the shared folder. **Overview** shows the status with **Start**, **Stop**, **Restart**, or **Try Again**, **Copy Details** and **Open Troubleshooting** after a failure. **Settings** has **CPUs** and **Memory** (each warns when it could crowd out the rest of the Mac; while the sandbox runs, its Memory is taken out of the Server → Memory Safety model load budget), **Agents Kept Warm** (how many agents and workflows keep a container running at once, scaled to this Mac's memory by default; another one joins by restarting the sandbox, which waits for running commands, background jobs and MCP requests and never stops them: queued tasks wait as *sandbox busy*, and anything else gets a *sandbox is busy* error to try again), **Environments Kept on Disk** (how many agent and workflow environments, with their apk packages, stay between runs; never fewer than Agents Kept Warm), **Stop When Idle** (minutes with nothing running, counting a connected sandboxed MCP server as running, before the sandbox stops to free its memory; 0 keeps it running), **Network**, **Auto-Start** (when off, the sandbox starts the first time an agent runs a command) and **Workspace** (**Open in Finder**); CPU, memory, Agents Kept Warm, Environments Kept on Disk and Stop When Idle changes take effect with **Restart to Apply** (or **Save** while it is stopped). **Network** is read-only: each agent's own **Sandbox Network** and **Allowed Domains** (Agents → the agent → Sandbox) decide it. When agents with different settings share the sandbox it shows **Filtered per agent**: each agent's web traffic goes through a filter that applies its own setting, and other connections such as SSH are blocked. **Agents & Environments** lists each agent's Linux user, network, packages and disk use, with **Open in Finder** and **Reset…** (resets the environment: removes apk packages and other changes outside the agent's home folder; restarts the sandbox if that agent is running). **Troubleshooting** (collapsed) has the last failure, **Provisioning Preflight** (**Run**, **Copy JSON**), **Run Diagnostics** and **Logs**. **Danger Zone** has **Reset Sandbox** and **Remove Sandbox**; both keep every agent's home folder and the shared folder.
- Agent Runtimes (Capabilities → **Agent Runtimes**): **Test** and **Sign In** (registering, editing, and deleting runtimes is also declarative, `harness_runtimes`).
- Devices (Sharing → Devices; formerly General → Sync and Capabilities → Mobile): your Macs and your iPhone in one sync account, end-to-end encrypted, with no account to create; the Sync topic explains what syncs, pairing, recovery and common questions. **Sync** has **Sync Chats**, **Find Devices** (**Same Network** or **Anywhere (Beta)**; when the first iPhone joins, the Mac asks once whether to switch to **Anywhere (Beta)**), **Run Agents for My Other Devices**, **Status**, **Waiting to Send**, **Older Messages** (while older history downloads; it pauses on a metered or Low Data network and in Low Power Mode) and, after an update, **Earlier Chats**. When **Same Network** finds none of your other devices for a while, **Your Devices Aren't Connecting** offers **Use Anywhere**. Each connected device says whether it's **Connected directly** or **Connected through a relay server**. **Devices** lists this account's devices, with **Remove Device…** in each other device's … menu; its confirmation defaults to **Remove and Change Phrase**, with **Remove Only** for a wiped device. **Add a Device** → **Show Code** is the one way to add a device: scan the code with the Osaurus iPhone app, or paste the pairing link into **Join Another Device** → **Join…** on another Mac. **iPhone** has **Keep Mac Awake for iPhone** (prevents idle system sleep only while an iPhone is in the account and **Run Agents for My Other Devices** is on) and **Continue iPhone Chats on This Mac** (a chat this Mac answered for your iPhone opens in front when you come back); your iPhone uses this Mac's agents only while **Run Agents for My Other Devices** is on. **Recovery** has **Recovery Phrase**, **Restore From Phrase** and, when this Mac has an Osaurus ID, **Use My Osaurus Recovery Phrase**; a linked Mac whose sync keys are lost shows **Unlock With My Osaurus Recovery Phrase**. **Storage** shows **Synced Chats**, **This Mac Only**, **Attachments** and **Total on Disk**. **Support** → **Support Report** → **Save…** writes connection details and recent sync logs with no chat content, titles or keys. **Sign Out** has **Sign Out and Keep Chats** and **Sign Out and Remove Chats**. **iPhone** also links to **Mobile** (Sharing → Devices → Mobile, kept for one release) for an Osaurus iPhone app that doesn't offer Sync yet: **Generate 6-Digit Code** (needs local network access; **Allow** turns it on), **Your iPhone** with **Unpair**, **Remote Access for This iPhone** (relay for the paired iPhone's agents) and **Keep Mac Awake for This iPhone**. Once an iPhone joins with **Add a Device**, this Mac turns the 6-digit pairing off and the page says the iPhone uses Sync. UI-only; settings are saved in `~/.osaurus/config/sync.json`.
- Vault (General → Vault): the one place to add, find and change any API key, token, password or variable that agents, MCP servers, plugins, channels and workflows use. **Add Key** opens a sheet with **Name**, **Who Can Use It** (All agents or one agent), **Value**, **Description**, **Hide Value** (off makes it a plain variable, which can span several lines for PEM keys; values are up to 64 KB) and **Agents Can Use This When Running Code** (the sandbox gets it as an environment variable). The page has three tabs. **Your Keys** starts with **Missing Keys** (what something you set up still needs, such as a workflow installed without its keys, with **Set**, which saves the value for all agents; a row notes when some agents already have their own value, since runs without an agent use only shared values), then **All Agents**, the shared keys: click a key to edit it. The agent picker beside the search field switches to one agent's keys, where **Use a Different Value** gives that agent its own value and **Use the Value for All Agents…** removes it after you confirm with **Remove Own Value** (a key's … menu also has **Use a Different Value For**). **Show** and **Copy** ask for Touch ID or your password; the value hides again after a few seconds. **App Keys** lists model provider, web search, voice, Hugging Face and GitHub keys, each with a line on what it is for, editable here or in their own pages (**Text-to-Speech Server**, the API key for the OpenAI-compatible speech server, shows only while Voice → Text to Speech → Advanced → Engine uses that server or a key is still saved; its … menu has **Open Voice Settings**), and **Accounts** lists every sign-in as sessions grouped by service (MCP servers, model providers, workflow connections, Discord and Telegram bots, Slack workspaces): **Add Session** (or **Sign In**) signs in another account, a session marked **Default** is what agents without their own use, and each session's … menu has **Rename…**, **Make Default**, **Sign In Again**, **Sign Out** and **Remove…**. Discord, Telegram and Slack are the exception: their bots and workspaces are added, renamed and removed in Settings → Channels, so their cards have **Manage in Channels** and each bot's … menu has **Make Default** and **Open in Channels**. On **Accounts** the same picker shows one agent and lets you pick its session per service; the Orchestrator, the Architect and runs on shared keys always use the default. Each extra Discord or Telegram bot and each extra Slack workspace is its own channel account in Settings → Channels, receiving and answering on its own; an agent given a bot here also posts its own channel messages through that bot. While you search, each tab shows how many of its items match. An agent's **Sandbox** row lists the same keys for that agent with **Open Vault**. UI-only; a config document can point at a shared key with `credential:KEY`.
- Developer Tools → Tasks: queues (**Add Queue**; each queue's **Max Concurrent Tasks**, **Max Waiting Tasks**, **When Full**, **Start Order** and **Paused**; **Name** and **Delete Queue** for queues you made). Which queue an automation uses is declarative (`automations[].delivery.queue`).
- Permissions: macOS TCC grants (Accessibility, Screen Recording, …). Tool Auto/Ask/Deny policies and **Auto-Allow All Tool Calls** live under Tools & MCP → All Tools.
- Tools & MCP: the page is **Services** (connected MCP services, **Add Service**, and the **Directory** of services you can add, filterable by category chips such as Legal, Finance & Accounting, and Healthcare & Life Sciences); **All Tools** (every tool with its permission policy) and **Plugins** (native plugin registry) are buttons in its header.
- Web Search: **Status** (whether search works, the categories it covers, connected providers and built-in sources), **Premium Search**, **Test Search** (runs the same search agents get), **Search Providers**, **Built-in Sources** (each with a test button and a switch), **Category Preferences** (which provider a category tries first) and **Custom Providers** (**Add Custom Provider** takes a JSON definition of any REST search API).
- Images & Video: image and local/cloud video job permissions and recent video jobs, with links to **Default Image and Video Models** (Model Defaults) and **Download Image Models** (Local Models → Image).
- Access (Sharing → Access): who can reach your agents from outside this Mac. **Remote Access** lists each agent with its state (**On**, **Off**, **Connecting**, **On another Mac**, **Couldn't connect**) and its switch; turning it on asks once to confirm. **Guests** lists everyone holding a guest link to one of your agents, by name, with **Revoke**. **Shared With You** lists agents people shared with you through a guest link (teammates' agents are in Workspaces). **Model Sharing** → **Share My Models for Inference** lets teammates, guests and peers run the models you expose in Server → Models. UI-only.
- Privacy & Security: data collection (Send Crash Reports) and **Activity Log** (**Keep Activity History** retention, **Store Prompts and Responses**, **Review Activity in Insights**) on the page, then **Privacy Filter** (the redaction filter, AI detection, per-provider overrides, background-request review), **Detection Rules**, **Data & Storage** (encryption at rest, plaintext backup and key, stores needing attention, and File History), and **Permissions** (macOS grants). Detection models are in Local Models → Privacy Detection; the detection model in use is Model Defaults → **Detection Model**.
  - Privacy & Security → **Detection Rules** has five sections: **Detection Patterns** (built-in phone — international and North American — email, URL and Luhn-valid card numbers), **My Regions** (the countries whose national ID / tax / health / bank presets are on by default; the first chip is detected from the Mac locale, **Add region…** opens a searchable picker over every country, removing a region never disables anything), **Preset Rules** (ready-made patterns grouped **My regions → Global → Other regions**, each group with **Enable all** / **Disable all**, a search field, and a **Suggested for …** banner when a home-region preset is off; US SSN is the `us.ssn` preset here, not a built-in), **Custom Rules** (**Add Rule**), and **Test Your Rules** (dry-run tester).

## Apple Apps (built-in)

Osaurus ships native tools for Calendar, Reminders, Contacts, Notes, Mail, Messages, Maps & Location, Music, and Shortcuts. They are **off by default** for every agent and are turned on per custom agent under **Agents → Abilities → Tools**, where each app is a group in the tool picker (Calendar, Reminders, …) listed above the plugin and MCP groups. The group's master checkbox — or any row switch, marked **Per app** — turns all of that app's tools on or off together; individual tools are not toggled separately. Turning an app on (in an existing agent or the New Agent card's Tools → **Customize**) asks macOS for that app's permission right away (Calendar, Reminders, Contacts, Location, or Automation for Notes/Mail/Messages/Music; Messages reading needs Full Disk Access via System Settings). A denied grant does not flip the switch back — the group header shows a **Permission needed** badge; clicking it re-asks for any grant macOS can still prompt for and then opens the System Settings pane for whatever is still missing (Full Disk Access, or an Automation grant that was denied). Sending mail or messages and running deletes always show an approval card; **Allow for This Conversation** never covers them. The Default agent (Orchestrator) has no Apple app groups in its picker and never calls these tools; it manages them on custom agents through `osaurus_config` (`capabilities.apple_apps`, the full list replaces the set, `[]` turns all off) and can provision a new agent with apps in the same call. The former `osaurus.calendar` / `.reminders` / `.contacts` / `.notes` / `.mail` / `.messages` / `.maps` / `.music` plugins are superseded by these built-ins.

Unknown-Model Metadata Fallback on the same Cache panel does **not** constrain local models. Use Context Window Cap to lower the window.

## Delegation memory checks

**Swap Local Models for Subagents**, under Settings → Agents → Delegation →
Local Models & Memory, is shared by custom agents and the Orchestrator. It applies
to local text delegation (including batches, background and resumed children),
Browser Use, Computer Use and dedicated AppleScript calls. On swaps the exact
invoking model out and restores it after the child. AppleScript's separate
keep-warm policy can defer that restoration for back-to-back calls; changing
the swap or warm setting settles the previous lease before the next run.

Off keeps the exact invoking model resident for the child's lifetime, including
under Server Strict. Only that job's newly loaded child is cleaned up afterward;
an already-resident shared target is not evicted. Memory checks may refuse a child,
but never fall back to evicting the parent. The redundant experimental coexistence
switch was removed; its old configuration key is retained only for compatibility.
If the parent was already unloaded, Off does not reload it. Same-model
and remote children do not need a swap. Local image jobs and context compaction
use this same parent-swap setting. The image Load policy controls only image-model
cleanup after the job; restoring a swapped parent always drains and unloads the
image model first. Independent automation runs (schedules, folders, webhooks) and
background helpers do not gain permission to evict unrelated chat models from
this switch. An automation-started agent's nested delegation uses that run's own
invoking model.

Settings → Agents → Delegation → **Local Models & Memory** → **Check Memory Before Delegating**
is one shared setting for the Orchestrator and all custom agents, not a per-agent override.
It defaults to On. It budgets child state, reuses already-resident weights, and can
split a batch or refuse a child under low headroom or elevated memory pressure.
Reclamation waits for active GPU work to drain and then takes a fresh host sample;
another delay cannot guarantee that the OS pressure or available bytes will change.

Off bypasses delegation RAM admission and before/after-handoff memory preflights,
including warning/critical pressure and unavailable estimates. Allocation failures
or crashes remain possible. Permissions, model ownership, cancellation and explicit
concurrency limits still apply. Server → **Memory Safety** load budgets are separate;
**No Automatic Limits (Dangerous)** removes automatic load caps there, while explicit
advanced overrides remain in force. Disabling the delegation check does not silently
rewrite those server settings. Decisions report `ram_safety_enabled`; when false,
`ram_slots` is diagnostic and does not limit the admitted capacity.

## Native MTP

Speculative Decoding defaults to **Default**, which resolves from the selected
bundle. Qwen Flash-Next bundles with a usable native MTP head start **On
(Adaptive)**, including supported affine and JANGH variants. Qwen 27B uses a
compatible bundled DFlash2 drafter automatically when one is present. A bundle
without compatible draft support runs ordinary autoregressive decoding.

The model picker shows **Off (AR)** or **On (Adaptive)** before weights load.
The runtime chooses depth; there are no manual D1/D2/D3 buttons. Explicit Off
turns speculation off, including external and bundled drafters. Saved explicit
choices survive reload. Legacy manual depths migrate to Adaptive and are
re-evaluated by runtime admission. **Reset to default** restores the selected
bundle's policy, so a capable bundle can show Adaptive again. Included evaluations
and benchmarks inherit that policy unless explicitly overridden.

On is a request, not proof that a particular request uses speculation. Unsupported
media and schema-constrained requests run AR. Server → Settings → **Speculative
Decoding** shows the loaded model's actual resolution and reason. Sampling stays
bundle-driven unless explicitly overridden. Remote models do not expose this
local control.

## Local model memory

Server → Settings → Model Memory contains **Keep Model Loaded** (off by
default) and **Unload After** (30 seconds by default). Models load when you
send a request. With Keep Model Loaded off, idle weights unload after the
timeout, or immediately when their last chat window closes. Active requests
finish first; another open window or active background/API request is protected.
Closing a chat does not shorten an unrelated API client's timeout. After an
unload, the next message reloads the model before it answers; the reply row
reads **Loading model…** while that chat's load runs.

Enable Keep Model Loaded to retain weights across idle time and window close.
Manual unload, model switching, changing settings that require a reload, and
quitting can still unload them. Saving a residency change also updates models
already idle in memory. This setting is UI-only, not declarative chat config.
An older 15-minute default migrates once to 30 seconds; other saved durations
and explicit Keep Model Loaded choices remain unchanged.

macOS manages swap. Osaurus no longer shows swap warnings or requires a
“Use Anyway” confirmation. Actual model-load failures still appear normally.

## Where settings are stored

Config JSON lives under `~/.osaurus/config/` (`server.json`, `server-runtime.json`, `chat.json`, `default-agent.json`, `agent-delegation.json`, `memory.json`, `sync.json`, …). Chats live in the sync store under `~/.osaurus/sync/`; the older `~/.osaurus/chat-history/` database is kept, unchanged, as a backup after its chats are copied in. Secrets live in the macOS Keychain; the Vault's list (names, who can use each, and variable values) is `~/.osaurus/credentials/index.json`, and which key an MCP server, plugin, channel or workflow uses is `~/.osaurus/credentials/bindings.json`.

### SSD cache controls

Normal cache filling and eviction are silent. Cache state is available in the
context-budget popover and Live Activity; there is no inline capacity-notice
popup or suppression setting.

**Clear SSD Cache** remains available in Cache settings and removes indexed
conversation cache files and linked companion data. Chats and model weights are
preserved. Clearing can make the next reply slower while cached data rebuilds;
it does not increase the cache limit. Save directory changes before clearing the
SSD cache; Clear is disabled while the displayed directory differs from the saved
directory. Clearing remains available when prefix reuse is disabled.

Disk Cache Size left blank uses **Automatic**: 30% of free space plus the cache's indexed payload bytes, including companions. Cache growth therefore does not shrink its own quota. An explicit percentage greater than 0 and up to 100 uses the total volume size without a 25% or 30% ceiling. It sets a maximum, not a reservation. Settings shows a red advisory when the limit exceeds currently available space or free space is low; the selected limit is not reduced. Existing percentages and legacy GB choices are preserved. Editing the percentage field replaces a legacy GB choice; clearing an explicit percentage selects Automatic. For a saved legacy GB choice, click **Use Automatic Cache Size**, then Save Changes.

Saving only the disk size updates resident models without unloading their weights. A decrease is enforced at the next cache write. Low free space produces an advisory and does not silently disable caching. Prefix Cache remains the master reuse switch; with paged RAM off, SSD reuse can still operate independently.

Cache controls are individually searchable: **Prefix Cache**, **Enable GPU Cache**,
**Block Size (tokens)**, **Max Blocks**, **Disk Cache**, **Disk Cache Directory**,
**Disk Cache Size (% of disk)**, **Clear SSD Cache**,
and **Re-derive SSM State After Generation**. Each result opens Server → Settings
→ Cache and scrolls to that control. Prefix Cache controls all reuse; Enable GPU
Cache controls the optional RAM tier, Disk Cache controls SSD reuse, and the
SSM option retains architecture-specific companion state for hybrid models.

### Concurrency and prompt processing

- **Server → Concurrency & Batching → Concurrent Sessions** sets the shared BatchEngine ceiling for same-model local jobs and local subagents. Continuous Batching must be on for concurrent decoding. Memory Safety overrides and current occupancy can reduce the effective limit displayed below the field; an empty override uses the Memory Safety profile.
- **Server → Concurrency & Batching → Prompt Prefill Chunk Size** sets how many prompt tokens are processed per prefill step. Empty uses the engine default. This is not the context window or the response token limit.

Search settings or ask Settings Help using either exact control name to navigate directly to it.

### Image sampling controls

In **Local Models → Image**, open **Generate** or **Edit** for an installed local bundle. **Sampler** and **Scheduler** list the choices supported by that bundle; **Bundle default** preserves its native behavior. **Timestep shift** appears only when the bundle supports an override. Leaving it empty preserves the default. Turbo bundles with a fixed sampling schedule reject alternate schedules or shifts. The same optional `sampler`, `scheduler`, and `shift` fields are accepted by the local image API and image tool; unsupported provider requests fail instead of silently dropping them.

**Live previews** in the local Generate/Edit panel shows an optional small image every five denoising steps. API/tool callers can set `preview_interval` and `preview_max_pixel`. Previews are off by default, may be dropped when busy or under memory pressure, and never replace the saved final image.

### Keeping model weights resident

Server → Memory Safety → **Keep Model in Memory** requests GPU residency while a local model is loaded. It is on by default when the model fits the GPU working-set ceiling and the OS reserve. Other apps may slow down because wired pages cannot be reclaimed. Turning it off permits the OS to evict model pages, which can slow replies under memory pressure. Saving changes reloads the model before its next request. This setting does not change **Keep Model Loaded** or the idle unload timer. A model that does not fit still loads in Safe Auto with an advisory; Strict retains its admission checks.

In **Resolved Plan**, **Load Allocator Cap** is a freed-buffer reuse target during loading. Inference uses a separate process-wide target based on loaded models, the active execution path, and admitted headroom. **Allocator Cache Cap (MB)** bounds those selected targets after reload; leaving it blank preserves the profile's load target and runtime-managed inference reuse. This is MLX's soft reuse policy: a whole released buffer can cross the target, and lowering the target does not immediately purge the existing pool. The next allocation trims excess cached buffers. It does not limit live model weights, KV state, or physical RAM. `/admin/cache-stats` reports the selected process-wide target at `memory_safety.memory_status.cache_limit` and actual occupancy at `mlx_cached_bytes`; neither belongs to one model or session, and the two values can differ. The existing `load_allocator_cap` and `inference_allocator` labels remain unchanged.


In **Images → Image Models**, open **Generate** or **Edit** for a FLUX 3 Image Klein bundle.
**Width** and **Height** in the Generate/Edit panel and chat size picker accept custom dimensions and snap on Return to multiples of 16 within the bundle's declared 64–4096 range. **Steps** in the panel or chat accepts a typed count; FLUX 3 has no fixed maximum. Choose **Default** in the chat size picker to restore unsized edits (the first prepared reference determines the canvas).

unset so the runtime uses the first prepared reference (and crops a padded single reference back to its fitted box).

## Per-agent generation defaults

**Show Response Metrics** lives in a custom agent → General → Configure → Advanced Settings (a new agent gets it there after **Create Agent**). It is off by default. Enable it to show existing measured token count, tokens per second and timings below responses. More → Inspect response keeps the same measurements either way. Missing measurements are not invented. This display preference is saved per custom agent and exported as `agents[].show_response_metrics`, separately from generation settings; it does not change tokenization, sampling or recorded usage.

**Show Follow-Up Suggestions** lives in a custom agent → General → Configure → Follow-Up Suggestions. It is on by default; turn it off to hide the suggested next questions under that agent's replies (useful for agents that end turns by asking you something). It only narrows Settings → Chat → Suggest Follow-Up Questions, which turns the feature on for every agent. While it is on, the model picker beneath it chooses the model that writes the suggestions (default: the shared Core Model). Saved per custom agent and exported as `agents[].follow_up_suggestions`. The Architect never shows follow-up suggestions, and no agent shows them while it is waiting on its own question, prompt card or workflow form.

Settings → Agents → a custom agent → General → Configure → Advanced Settings → Generation Overrides groups Sampling, Length & reasoning, Repetition and Reproducibility. Inherit preserves existing defaults; Custom values save only for that agent. Known local defaults display their Model, Server, App or Runtime source. Unavailable provider defaults stay labeled as defaults. Thinking / Reasoning effort choices come from the selected model. Only the advertised effort IDs appear; boolean-only models show Thinking On/Off instead. Speculative Decoding appears for eligible local native-MTP or compatible drafter bundles, including DSpark, Uno and DFlash 2. Inherit follows Server settings; explicit Off (AR) disables drafting for this agent, and On (Adaptive) overrides the inherited mode without changing sampling or shared Server settings. Preparing a missing head waits for active requests and respects existing residency and RAM settings. It may require a model reload. When the agent has an explicit speculation override, the chat model picker shows and edits that saved agent value; reset removes it. Inheriting agents retain the existing Server-wide picker behavior. Request eligibility can still select ordinary decoding. External harnesses keep their own generation settings.

When a local bundle declares native DiffusionGemma, Temperature, Top P, Top K, Min P and the three repetition penalties remain visible but read-only because that model uses its native denoising schedule. Saved Custom values are marked as not used by this model and remain saved when you switch models. Selecting an applicable model restores those controls with their original values. Max Tokens, Seed, Stop sequences and the model's declared prompt controls remain available. This does not change generation defaults or the denoising schedule.

Stop sequences uses exact-text chips: enter a string and press Enter or Add; remove a chip with its × button. Save/Create also includes a pending string. Custom starts with no additional strings (`[]`); model end-of-turn tokens still apply. Advanced: chat template parameters → Show reveals Template parameters (JSON). Custom starts with `{}`, an object of additional variables, not the full chat template. Conversation, tools and special-token variables cannot be replaced. Switching modes preserves existing edits; select Inherit to remove an override. Invalid custom fields show an inline error and cannot be saved. Inherited previews do not change saved settings or the model/server defaults.
